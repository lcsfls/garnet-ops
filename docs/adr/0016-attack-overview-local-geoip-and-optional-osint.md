# ADR 0016: Attack overview with local GeoIP and optional OSINT

> **Status: superseded by ADR 0025 (removed in 0.0.4).** The module was removed when GarnetOps became a pure developer pipeline. The text below is kept as the record of the decision; it describes the last version that has the module, the tag `v0.0.3`.

- Status: superseded by ADR 0025 (removed in 0.0.4). Earlier status: proposed (2026-10-22), for review by the maintainer
- Date: 2026-10-22
- Implements: ROADMAP Phase 4 "Attack overview: local GeoIP (DB-IP Lite), optional OSINT enrichment";
  mockup view "Attacks"
- Builds on: ADR 0015 (the Wazuh sync stores aggregated source addresses), ADR 0004 (vault: the API
  seals, only the worker opens), ADR 0010 and ADR 0015 (outbound address rules), ADR 0013 (AI
  summaries on numbers only), AGENTS.md rules 1, 3 and 7 (security first, clean third-party data,
  no sensitive data in the repository)

## Context

ADR 0015 made the Wazuh sync store the source addresses of authentication-failure and attack
alerts (the 100 busiest per period). This ADR gives them a screen: **Infrastructure, Attacks**, a
world map and tables that show where failed logins and attacks come from, and, if the customer
switches it on, a reputation score per address.

Three facts shape the design:

- **The addresses come from outside.** A source address is written by whoever attacks. The text
  around it (rule groups, agent names) comes from Wazuh and is hostile input like everything in
  ADR 0015.
- **Source addresses can be personal data** (GDPR): an address can identify a person, and an
  attacker's address may be a hacked home router. They must not be kept longer than needed and
  must not leave the network without a decision by the customer.
- **The core promise** (AGENTS.md): no customer data leaves the network unless the customer
  configures it. Location must therefore work offline from a local table, and every outbound
  call of this feature is off by default.

Data and licences (AGENTS.md rule 3):

- **DB-IP "IP to Country Lite" and "IP to ASN Lite"** are CC BY 4.0 (attribution required), CSV in
  gzip form, updated monthly. They are **never bundled**: not in the repository, not in an image.
  The customer loads them, by hand or by an opt-in download.
- **MaxMind GeoLite2** has an EULA that forbids redistribution and is not used.
- **Natural Earth** 1:110m country shapes are public domain; packaged as TopoJSON by world-atlas
  (ISC). The shapes are converted at build time to SVG paths in the repository
  (`apps/web/src/assets/world-map.ts`, generated by `scripts/build-world-map.mjs`). No tile server, no
  map library, no request at run time.
- **AbuseIPDB** (check API) is the one OSINT provider implemented. Its terms could not be read
  from the build environment (no network access); see section 6.

## Decision

### 1. The data the page is built from

The sync (`apps/worker/src/wazuh.ts`) keeps asking the indexer with **fixed query templates** (ADR
0015 section 2); the attack part of those templates grew, additively, and takes nothing but the
enumerated period:

| Stored | Content | Bound |
| --- | --- | --- |
| `wazuh_source_ip` (existing, three columns added) | per period: address, alert count, rule groups, **first and last alert time**, the **agents it attacked most** (id, name, count) | 100 per period, replaced at every sync |
| `wazuh_attack_window` (new) | per period: **all** attack alerts (also those without an address), distinct sources (approximate), the most targeted agents, and the previous period's numbers and its addresses (for "countries" against the period before) | one row per period, replaced at every sync |

The previous period's addresses are never put into the snapshot JSON, which stays numbers only
(tested). Everything parsed from Wazuh passes the same strict parsers as in ADR 0015: timestamps
between 2000 and 2100, counts bounded, agent ids matched against a pattern, names cleaned and cut.

### 2. Local GeoIP

**Tables.** `geoip_dataset` (one row per load: kind, source `import` or `download`, release month
from the file name, row count, SHA-256 of the compressed file, state), `geoip_country_range` and
`geoip_asn_range` (`inet` start and end, a btree index on dataset and start). Lookup is one index
probe per address and table: the range with the largest start at or below the address, kept only if its
end covers it. That is correct only if ranges do not overlap, which the reader enforces.

**Reading a file** (`packages/core/src/geoip.ts`) is a stream and treats the file as hostile:

- gzip with a **cap on the compressed bytes** (64 MiB, also declared up front) and on the **inflated
  bytes** (256 MiB), counted as data comes out, so a compression bomb stops at the cap and not at
  memory. The read ends when the consumer stops; the source is closed.
- **Lines** are cut at 1 KiB: a longer line ends the read (no buffer grows without bound).
- Each line is parsed as RFC 4180 CSV and validated alone: two addresses of the same family with
  start not after end, a two-letter country code or an AS number up to 2^32 - 1 and a cleaned
  organisation name (control and bidirectional characters removed, 200 characters). **Ranges must be
  ascending and must not overlap**: a line that does is skipped and counted. IPv4-mapped IPv6 addresses
  are read as IPv4.
- A file fails when it is empty, has more than 3 million ranges, or has more invalid lines than the
  larger of 10 and 0.1 %. A country file given as ASN file (or the reverse) is recognised by the
  field count and refused with that reason.

**Loading** (`packages/db/src/geoip.ts`) happens in **one transaction**: ranges are inserted in
batches while the file is read; only when the whole file has passed is the new dataset made active and the
old one deleted. Any failure rolls everything back, so **the last good dataset stays**, and the reason
is stored as a short code (the last failure per kind). One load per kind at a time (advisory lock). The
release month and a checksum are recorded; the page warns when the data is older than three months.

**Two ways in, both owner/admin only, both audited:**

- **Manual import** (air-gap capable). `PUT /api/v1/attacks/geoip/{country|asn}`, a raw gzip body,
  streamed to the parser. The route needs a **recent sign-in** (step-up), a `Content-Length` of at
  most 64 MiB, and is rate limited; the global 1 MiB body limit is lifted for this one path and method
  only (`apps/api/src/lib/body-limit.ts`, tested). The whole import has a 10-minute deadline however slowly the
  file arrives. The file name (not trusted for anything but the month) gives the release month.
- **Opt-in monthly download** by the worker (`apps/worker/src/attacks.ts`). **Off by default;
  with it off no request is made.** Switching it on needs a recent sign-in and is audited. The
  UI shows the exact URL pattern, `https://download.db-ip.com/free/dbip-{country|asn}-lite-YYYY-MM.csv.gz`.
  The worker (`apps/worker/src/outbound.ts`):
  - connects only to that fixed host, whose name it resolves itself: **every answer must be a public
    address** (private, loopback, link-local, metadata and reserved addresses are refused), and the address that
    was checked is the address connected to; an address literal is checked too;
  - TLS 1.2 or newer with the system certificate store, certificate and name always verified;
  - **no redirects** (a redirect is an error), only GET, no cookies or credentials;
  - connection timeout, an overall 5-minute deadline that also covers a body that drips, the compressed and
    inflated caps above, and the same validation and transactional load as a manual import;
  - tries this month's file and, if DB-IP has not published it yet (404), last month's; asks at most every
    12 hours; does nothing when the loaded month is current.
  Every result is audited (`attacks.geoip_downloaded`, `attacks.geoip_download_failed`) and shown in Settings.

The dataset is installation-wide public data and therefore has no organisation column; the settings
(download on or off, retention, OSINT) belong to the organisation.

### 3. Enrichment

The page and the AI summary read country, AS number and organisation **from the local tables
only** (`lookupIps`, one batched query; 10,000 addresses take well under a second, measured in the test).

- **Internal addresses are labelled "Internal" and never looked up**: private (RFC 1918, shared address space
  and unique-local), loopback, link-local, multicast and other reserved addresses (`classifyAddress`
  of `ai-endpoint.ts`, the same policy as everywhere else). The documentation ranges are public to this
  policy, which keeps test data realistic.
- A public address the data does not cover is "Unknown".
- The page says in several places that **location is approximate**: it shows where an address
  range is registered, not where a person sits.

### 4. The page

`Infrastructure, Attacks` (route `/attacks`) is listed only while a Wazuh connection exists, like XDR; without one,
the page and **Settings, Attack overview** say how to connect. Everyone in the organisation reads; owners and
admins configure.

Periods 24 hours, 7 and 30 days; four key figures (attack alerts, source addresses, countries, the most targeted
machines) with the **change against the previous period**, two more on wide screens; the **map**; **countries**,
**networks** and **machines** lists (the table alternative: the same numbers, complete, keyboard operable, with a note
for countries too small for the 110m shapes); and the sortable, filterable, searchable **address table** with cursor
pagination (`apps/api/src/lib/paginate-memory.ts`, the same envelope and cursor semantics as the SQL pages), more
columns from the wide step on, filters in the URL, and links from machines to Servers or XDR.

- **Map colour** is a single hue (steel blue, the information colour) in five steps on a square-root scale,
  defined as design tokens for both themes; **never a severity colour**, never burgundy. Countries without alerts are
  neutral. The CSP forbids inline styles, so the fill is a class per step.
- **Addresses are plain text** with a copy button: no link, no markup, no external lookup. The page links to the
  outside only for the DB-IP attribution and, **when OSINT is switched on**, to the provider's page for that address
  (`rel="noopener noreferrer nofollow"`, new tab).
- Attribution "IP geolocation by DB-IP (db-ip.com), CC BY 4.0" (linked) and "Map: Natural Earth (public domain)" are
  on the page, and in `docs/COMPONENTS.md` and the README.

### 5. Retention (GDPR)

- GarnetOps keeps **only the latest aggregate of each period**, replaced at every sync (15 minutes). No history of
  addresses is built.
- A **retention period** (default 90 days, 1 to 365, set per organisation in Settings) is the backstop: an hourly
  worker job deletes source addresses, attack numbers (which carry the previous period's addresses) and OSINT
  results older than the period. In normal operation nothing gets old; the job matters when the sync stops, when
  a connection's data is orphaned, and when the period is shortened. Raising the period needs a recent sign-in.
- **"Delete stored addresses now"** (step-up, audited) erases them at once, for an erasure request.
- Removing the Wazuh connection deletes them with it (foreign key cascade).
- The audit log holds counts only, never an address.
- Mail and notifications do not include addresses (unchanged).

### 6. Optional OSINT enrichment

A provider is a small description in `packages/core/src/osint.ts`: host, request builder, parser, key check, page
URL, and whether the maintainers have confirmed its terms. **AbuseIPDB** is the only one; another is one entry and one
parser.

- **Off by default.** Switching it on is an owner/admin action with a recent sign-in, audited, and requires
  **two confirmations typed in again every time**: that public source addresses are sent to the provider, and that the
  customer has checked that the provider's terms allow this use with their key. The settings screen says in plain words
  what leaves the network (public addresses of the busiest sources, at most N per sync) and that private addresses never do.
- **The customer's own API key**, sealed in the vault (new purpose `osint-api-key`, bound to organisation, record and
  purpose). The API seals; **only the worker opens**, for the seconds a run takes. The key is never returned, logged,
  audited or stored in clear (tested over the tables and the logs). Replacing or removing the key needs a recent sign-in;
  removing it switches OSINT off.
- **Worker-only calls**, over HTTPS to the fixed provider host with the rules of section 2 (public address only, TLS
  verified, no redirects, timeouts, a 16 KiB cap on the answer). The key travels only in a header.
- **Only public addresses**, **at most the top N** (default 20, at most 50) per sync, the busiest first over all periods;
  **results cached for 24 hours**; a **daily budget** (default 300, at most 900, and always below the provider's free
  tier of 1,000 checks a day), counted per UTC day across runs; a 401 or 403 (key rejected), a 429 (rate limit) or a redirect
  stops the run at once and is shown as a short code; three bad answers in a row end it.
- The answer is parsed field by field: an answer about **another address** is refused, the score must be an integer from 0 to
  100; only **score, report count and last report time** are stored. Nothing else the provider says is kept or shown.
- Switching OSINT off, replacing the key or the provider **deletes the stored scores**.
- **Terms.** AbuseIPDB's published terms and plan limits could not be read while building this feature, and the
  maintainers have not confirmed that a customer may use their own key this way on the plan they have (the free plan
  is commonly offered for non-commercial use). The provider therefore carries `termsConfirmed: false`: the interface and
  the implementation exist, the feature stays off by default, and **the customer's confirmation is required**, with a
  link to the provider's terms next to the switch. The maintainer decides whether to keep it switchable (open question).

### 7. AI summary

"Summarise with AI" on the page (only with AI configured and on) follows ADR 0015 section 11: the API stores a
pending summary and queues a job, **the worker builds the prompt and calls the model** through the same client and address
policy. The model receives **numbers only**: attack alerts, distinct sources and their previous values per period, and
alerts and sources per **country code** and per **AS number**, with a note that the lists cover only the busiest
addresses. **No IP address, no organisation name, no agent name, no rule group, no text from any alert or data file.**
Tests replay hostile organisation names, agent names and addresses and assert none reaches the model. The answer is
untrusted, labelled "AI suggestion", rendered by the safe Markdown renderer.

From ADR 0022 (section 7.6) the same numbers-only rule covers UniFi IPS events: counts of blocked and alerted events per
country code and AS number, in a block apart from Wazuh's, and never a signature, category, address or name.

### 8. Permissions, audit, errors

| Action | Who | Recent sign-in | Audit action |
| --- | --- | --- | --- |
| Read the page, the tables, the summary | every member | no | none |
| Ask for a summary | member and up | no | `ai.request` (kind `attack-summary`) |
| Open the settings | owner, admin | no | none |
| Import or remove location data | owner, admin | yes | `attacks.geoip_imported`, `_import_failed`, `_removed` |
| Monthly download on | owner, admin | yes (off: no) | `attacks.geoip_download_enabled`, `_disabled`; the worker audits each download |
| Retention up | owner, admin | yes (down: no) | `attacks.settings_changed` |
| Delete stored addresses | owner, admin | yes | `attacks.data_purged` (counts) |
| OSINT on, key set or replaced or removed, provider changed | owner, admin | yes (off: no) | `attacks.osint_enabled`, `_disabled`, `_key_changed`, `_key_removed` |

Errors stored or returned are short fixed codes translated in the web app (`GEOIP_ERROR_TEXT`, `OSINT_ERROR_CODES`);
nothing a file or a provider said ends up in an error, a log line or the audit log.

## Threat model

| Threat | What an attacker gains | Mitigation |
| --- | --- | --- |
| Hostile alert data (source address, rule groups, agent names written by an attacker) | Stored XSS, injection, memory growth, prompt injection | Strict parsers (ADR 0015), addresses must be valid IPs, groups from a fixed list, names cleaned and cut, counts bounded; the page renders text (React escapes), addresses are never links; the AI summary sees no text from an alert (tested with hostile fixtures, including in a browser) |
| Source addresses leave the network | Disclosure of who attacks the customer, possible personal data | Location is local; the download sends only a request for a fixed file; **OSINT is off by default**, needs step-up and two confirmations, sends only public addresses, top N, within a daily budget, with the customer's own key, and says so in the UI; audit entries; scores deleted when switched off |
| Falsified GeoIP data (a replaced file, a man in the middle) leads to misattribution | Wrong countries on the page; a wrong "this is internal traffic" is impossible because internal addresses are never looked up | Manual import by an admin with step-up and audit, with checksum and release recorded; download only over verified TLS from the fixed host (no redirects); sorted, non-overlapping, validated ranges; the page says locations are approximate and shows the release month |
| Decompression bomb, huge line, endless file, file that never ends | Memory, disk or time exhaustion of the API or worker | Caps on compressed (64 MiB) and inflated (256 MiB) bytes counted while streaming, 1 KiB lines, 3 million ranges, invalid-line limits, deadlines (10 min upload, 5 min download); loading in one transaction with a lock; tests with a 200 MiB bomb, valid-range bombs, a 100 kB line and an endless source |
| A failed or malicious import destroys the working data | No location data until someone notices | One transaction: the old dataset is replaced only after the whole new file has passed; the last good dataset stays; the failure reason is shown |
| SSRF through the download or OSINT calls | The worker connects to an internal service | Fixed hosts in code, never from the database or a form; the lookup refuses any answer that is not public and connects to the checked address; literals are checked; no redirects; response size and time caps |
| Stolen OSINT API key (database, backup) | The customer's quota and account at the provider | Sealed in the vault, opened only by the worker, never shown, logged or audited; removing it deletes it; the customer can revoke it at the provider |
| A member without rights changes the settings or loads data | Wrong data, outbound traffic, longer retention | Role checks on every write, step-up for everything outbound, data-replacing or retention-raising, organisation scoping, audit |
| Misleading numbers (the lists cover the 100 busiest addresses only) | Wrong conclusions | The page states the coverage ("105 of 120 alerts"), the countries figure counts only listed addresses, and everything is labelled approximate |
| Long retention of personal data | GDPR exposure | Latest aggregate only, replaced every sync, 90-day backstop (configurable), erasure on demand, cascade on removal |
| Misuse of the map (a country is blamed) | Reputational or operational harm | The map shows registration of address ranges, says so, and uses one neutral colour scale |

## Consequences

- Migration 0015 (additive): `geoip_dataset`, `geoip_country_range`, `geoip_asn_range`, `attack_settings`,
  `attack_osint_result`, `attack_summary`, `wazuh_attack_window`; three columns on `wazuh_source_ip`; secret purpose
  `osint-api-key`. New queue `attacks.summary` and the scheduled `attacks.maintenance` (hourly: retention, download).
  New audit actions `attacks.*` and an audit filter "Attacks". API under `/api/v1/attacks`.
- The sync asks the indexer for a few more small aggregations per period (minimum and maximum time, agents per address,
  a cardinality, and the previous period's addresses). They are fixed templates like the rest.
- GarnetOps stores no GeoIP data itself and ships none: a fresh installation shows addresses without countries until
  the customer loads the files, and says so.
- Not done: a history of attacks over time (by design, for privacy), IPv6-specific rules beyond what the data gives,
  a second OSINT provider, blocking or reporting addresses (GarnetOps only reads), and a check of AbuseIPDB's terms
  (open question above). The Wazuh 5.x field names remain as in ADR 0015.
- Every release is tested as an upgrade; the migration only adds tables and columns.
